(30.2) moron-proof reminder of how to set up / troubleshooting

* elpa keyring
package signatures are checked. on a new machine, run this once before
installing anything, or it fails with "failed to verify signature... no
public key...":

#+begin_src text
  M-x package-install RET gnu-elpa-keyring-update RET
#+end_src

if it still fails (e.g. an expired key), temporary workaround for the
current session only:

#+begin_src elisp
  (setq package-check-signature nil)
#+end_src

* startup speed
init.el and lisp/ are byte-compiled (the .elc files are not in git).
saving an .el inside emacs recompiles it. after a fresh clone, or edits made
outside emacs, recompile everything:

#+begin_src sh
  emacs --batch --eval "(progn (package-activate-all) (add-to-list 'load-path (expand-file-name \"lisp\" user-emacs-directory)) (byte-recompile-directory (expand-file-name \"lisp\" user-emacs-directory) 0 t) (byte-compile-file (expand-file-name \"init.el\" user-emacs-directory)))"
#+end_src

packages are activated from package-quickstart.el. it's generated per machine
and not in git, so run this once on every new machine (including linux).
package.el refreshes it on install/delete after that. without it emacs still
works, just loads packages the slower way. if it ever gets out of sync:

#+begin_src text
  M-x package-quickstart-refresh
#+end_src

check with ~M-x emacs-init-time~ (about 1s on the work laptop).
